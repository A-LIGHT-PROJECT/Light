- These guidelines are not mandatory to implement when making your language although recommended...
# Light Guidelines
1. Guidelines included in any version you're wanting to make a parser for must follow those guidelines
2. You must have 2 bytes for version control depending on the version of Light.
3. Any new guideline in Light can be added and you must follow it right away.
# Light26 Guidelines
1. Your syntax must be clear on what it is doing, however any type of syntax style can be allowed.
2. You must always have LIGHTINSTALL folder inside every compressed file for easy installation for the user, nothing extra should be added inside the folder.
3. Behavioral bytecode that has any relation to installing something or doing something inside an execution must not be activated unless confirmed.
4. Your language must include the execution of commands inside your environment.
5. A fix in Light26 means you must update your Light26 executable to match that fix.
6. Any new guidelines in Light26 before and during the era of Light26 can be added and you must follow it right away.
7. There shouldn't be a secret backdoor for viruses and dangers for the developer to accidently see.
